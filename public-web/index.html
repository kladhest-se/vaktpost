Vaktpost is an iOS app that reads the state of a pfSense firewall — clients, gateways, tunnels, logs — and shows it in a form you can take in from a phone screen. It is open source and free.

The name is Swedish for a sentry post: somewhere you watch the perimeter from and report what you see, without changing anything. That is the whole scope.

Set it up Read the source

Needs pfSense CE or Plus with the community REST API package, and an API key with read privileges. iOS 17 or later.

What it shows

Five tabs. Everything is assembled from what the REST API already exposes, with the joins and thresholds done on the phone.

Clients, in one list

pfSense keeps DHCP leases, the ARP table and static mappings as three unrelated views. Vaktpost joins them on MAC into one entry per device, so you can ask whether the printer is online without checking three screens. Tap through for the filter-log lines mentioning that address.

Throughput over time

The API reports lifetime byte counters, not rates. Vaktpost differences consecutive samples to get bits per second and keeps about half an hour of history per interface. A counter reset starts a fresh baseline instead of drawing a spike.

Alerts worth waking up for

Gateways down or lossy, services stopped, disk and memory pressure, the state table filling, certificates about to expire, CARP left in maintenance mode, IPsec tunnels down. Derived on device, so the thresholds change without touching the firewall.

Tunnels

OpenVPN servers and their connected peers, IPsec security associations with their child SAs, WireGuard tunnels with per-peer handshake state and transfer counts.

Rules you can actually read

Firewall rules filtered by interface, NAT port forwards, and aliases with their contents expanded. Searchable by description, address or port. Read-only, like everything else.

More than one firewall

Each has its own key in the keychain, its own TLS settings and its own refresh interval. Switch from a chip row on the overview. Useful if you look after several.

All four flavours

Latte, Frappé, Macchiato and Mocha, with all fourteen Catppuccin accents. Pick one flavour for light appearance and another for dark, or pin one regardless of what iOS is doing. The picker at the top of this page is the same set.

A home screen widget

Small and medium. Health, gateway latency, interfaces up and current uplink rate, with the age of the reading shown so a stale card is obvious.

It never writes

There is no POST, PATCH, PUT or DELETE anywhere in the client. Not disabled behind a setting — absent from the code. The API key you give it only needs read privileges, and if you scope it that way, the app physically cannot do anything else.

Keys live in the iOS keychain, one per firewall. They are never written to preferences, never sent anywhere but your own firewall, and never leave the device.

Setting it up

pfSense has no REST API of its own, so this depends on the community package. Four steps on the firewall, one in the app.

  1. Install pfSense-pkg-RESTAPI on the firewall. The project documents the install at pfrest.org.

  2. Turn on key authentication under System → REST API → Settings.

  3. Create a key under System → REST API → Keys, tied to a user with read privileges.

  4. Open Vaktpost, enter the firewall address and paste the key.

  5. Pin the certificate. pfSense ships a self-signed one, so connect once with untrusted TLS allowed, then tap Pin last seen certificate in the firewall's settings. After that the connection is accepted only if that exact certificate is presented. Re-pin when you renew it.

What it can't do

Worth knowing before you install it rather than after.

No push notifications

Alerts are computed when the app refreshes. Without a server of your own there is nothing to send a push, so the widget only advances while the app is open or iOS grants a background slot. If you need to know the moment a WAN link drops, you need a monitoring host, not a phone app.

No traffic analysis

pfSense has no DPI and the REST API exposes no per-client traffic accounting, so there is no top-talkers view of the kind a UniFi gateway gives you.

No IDS or IPS view

Suricata, Snort and pfBlockerNG have no endpoints in the REST API package, so their alerts cannot be read. Absent by necessity, not oversight.

No changes, ever

You cannot restart a service, toggle a rule or reboot the box from here. That is a design decision, not a missing feature.

Building it

The project is SwiftUI, targets iOS 17, and uses XcodeGen so there is no .xcodeproj in version control. Clone it, run make project, set your development team, and build. The widget is a second target and needs an App Group, which is declared in the entitlements files.
